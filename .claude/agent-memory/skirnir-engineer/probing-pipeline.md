DOC-11 Phase 0 (Foundations) AND Phase 1 (rotary setup: the rotary-safe probe primitive + the center-finder wizard) are implemented in skirnir. Phase 2 (180°-flip verify, runout report) is NOT.

**Why:** probing wizards are multi-step result-dependent sequences and skirnir had none of that machinery; the old `probe_z` fired `G38.2` then `G10 L20` unconditionally (a race protected only by alarm-ordering). Design + rationale: `docs/skirnir-probing-design.md` (§0 + Phase-0 subsections).

**How to apply (the three load-bearing pieces, all event/state-driven — no async await primitive):**
- `protocol/probe.rs::parse_prb_body` parses `<v0>,<v1>{,…}:<flag>` → 1..N f64s + bool, used by BOTH the async push and the `$#` poll echo. REJECTS non-finite values (`nan`/`inf` — Rust's `f64::parse` accepts them, and a NaN would poison the wizard math). `parse_line` types `[PRB:]` into `Response::ProbeResult{position,success}` AHEAD of the generic `Message` fallback; a malformed/non-finite body falls through to `Message` (never panics).
- The latch lives in the PURE reducer (`app/view_state.rs`): `ProbeOp{kind,awaiting,last}`, `ProbeKind`, `ProbeOutcome{Success{position}|Failure{reason}}`. Shell calls `view.begin_probe(kind)` at issue; the reducer captures the next `ProbeResult` (success/`:0`-failure) and FAILS the op on any intervening `Alarm`/`Error`. `fail_probe`/`resolve_probe` only act while `awaiting` (a late `[PRB:]` can't clobber a resolved op). `probe_op` is cleared on disconnect.
- The push-or-poll fallback + the result-gated zeroing are the PURE `app/probe_flow.rs::decide` (no egui/`Instant` inside) returning `ZeroZAction{Wait|Zero(line)|Fail|Poll|GiveUp}`; the shell's `pump_probe_z` (per-frame, after intents) only does the I/O it names. `PUSH_TIMEOUT=15s` → one `$#` poll, `POLL_TIMEOUT=2s` → give up, `ABSOLUTE_GIVE_UP=30s` from issue → unconditional give-up backstop (catches a fast probe whose `seen_cycle` never latched AND whose push was lost, else it would hang). The KIND-AGNOSTIC await/poll/give-up core is `await_action(polled, probe_finished, since_issue, since_poll) -> AwaitAction{Wait|Poll|GiveUp}`, SHARED by both `decide` (ZeroZ) and the wizard pump so they can't drift.
- **The `$#` fallback is gated on probe COMPLETION, not raw elapsed time.** A slow/no-contact probe legitimately travels >15s, and `$#` returns the LAST probe's result — so polling mid-cycle could zero off stale data. While `!probe_finished` it WAITS regardless of elapsed (up to the absolute backstop). `probe_finished` = "saw a cycle AND now idle"; startup-race guard requires a cycle observed first. **`is_probe_cycle_state` treats ANY non-`Idle` state as in-cycle** (incl. `Door`/`Sleep`/`Tool` suspends) — a probe is finished ONLY on a clean return to `Idle`; a genuine failure resolves via the Alarm/Error path so the gate isn't consulted there.
- **Probe is RELATIVE, zero is position-INDEPENDENT (critical fixes).** The probe line is wrapped `G91` … `G90` (per `docs/tlo-offsets.md`) — under `G90`, `G38.2 Z-d` would resolve as an ABSOLUTE target and crash. The deferred zero is built from the `[PRB:]` CONTACT machine-Z on resolution (`probe_flow::zero_z_line` → `G10 L2 P0 Z<contact_z − plate_thickness>`), NOT a pre-built `G10 L20`: L20 uses the current position, so a jog during the lost-push window would corrupt the zero. `PendingZeroZ` now stores `plate_thickness`, not a line.
- **Shared latch is KIND-GATED (cross-contamination fix).** `pump_probe_z` acts only when `op.kind==ZeroZ`; `pump_wizard` only when `op.kind==RotaryCenter`; the `probe_result` view (ZeroZ panel) renders only for `ZeroZ`. Starting a rotary touch clears `pending_zero_z`; starting a ZeroZ clears `self.wizard`. Otherwise one `[PRB:]` could fire BOTH follow-ups.

**Gotcha — dropped `Eq`:** `Response::ProbeResult` carries `Vec<f64>` (not `Eq`), so I removed `Eq` from the derive on `Response`, `Event` (engine.rs), and `Effect` (protocol/core.rs). `PartialEq` is retained; nothing keyed these in a hash/tree set, so it was safe. If you add a new variant with floats elsewhere, expect the same.

**Phase 1 — rotary center-finder (the headline wizard):**
- `app/rotary_probe.rs` — PURE rotary-safe probe primitive `rotary_safe_probe_lines(touch, params)` → 5 lines: `G53 G0 Z<clearance>` (machine-coord retract), `G90 G0 A<angle>` (ABSOLUTE index), `G4 P<settle>` (settle dwell), `G91 G38.2 <axis><signed depth> F<feed>` (RELATIVE probe), `G90` (restore absolute). The probe line NEVER carries an A word. `RotaryProbeParams` = bench-tuned clearance/settle/feed/depth with conservative defaults (surfaced in UI, not hardcoded silently).
- `app/rotary_center.rs` — PURE multi-step state machine `WizardState`/`WizardStep` (EnterDowel→ProbeYLeft→ReadyYRight→ProbeYRight→MoveToYc→**MovedToYc**→ProbeZTop→Review→Aborted). Each step has ONE meaning (don't disambiguate by readings). Math: `Y_c=(Y_left+Y_right)/2` (radius cancels in midpoint), `Z_c=Z_top−D/2`. ORDER ENFORCED by the type: `mark_moved_to_yc()` advances `MoveToYc→MovedToYc` and `begin_z_top()` only works from `MovedToYc` — so you cannot probe the top until the move-to-Yc was actually SENT (not just until the step was reached), else the top reads a chord. A failure (`:0`/alarm) → `Aborted{reason}`, no partial compute.
- **L2 not L20 (decision):** `offer_g10` emits `G10 L2 P0 Y<Yc> Z<z>` — Yc and z are MACHINE coords computed from the machine-coord `[PRB:]` readings, and `G10 L2` sets the WCS origin directly from absolute machine coords (so work-Y0 lands on the centerline regardless of tool position). `L20` would require the tool to physically be at the feature (it isn't). The line carries ONLY Y and Z — never A — so the rotary datum is untouched.
- **Z0 datum is operator-selectable (`ZDatum`, default `AxisCenterline`):** Y0 is ALWAYS the axis centerline (`Y_c`); only the Z word varies — `AxisCenterline → z_center()` (`Z_top−D/2`, wrap convention) or `TopSurface → z_top` (raw probed top, axis then at work-Z=−D/2). `z_center()` stays the axis math (shown in Review) regardless; `z_datum_value()` is what `offer_g10` writes. Held in `WizardState.z_datum`, set via `Intent::RotaryCenterSetZDatum`. UI: `views::rotary_z_datum_picker` (two selectable labels in the Review step) with a one-line clarification + a "G10 will set Z …" preview.
- Shell wiring: `wizard: Option<RotaryCenterRun{state, params, touch_fallback}>`; `pump_wizard` (per-frame, after intents) kind-gates the latch, folds a resolved result into the state machine then `view.clear_probe_op()` (consumed once), AND runs the shared `await_action` lost-push fallback per touch (`TouchFallback{issued_at, polled, polled_at, seen_cycle}`) so a dropped wizard `[PRB:]` polls `$#` rather than hanging. `rotary_center_move_to_yc` advances to `MovedToYc` only if the move was actually sent (`send_line` now returns bool). Intents: `RotaryCenterStart/Probe/MoveToYc/WriteWcs/SetZDatum/Cancel`. View: `views::rotary_center` (right column, below probe panel) reads `Option<&WizardState>`; the `MoveToYc` step shows only "Move to Y center", `MovedToYc` only "Probe Z (dowel top)".
- **Persistence is a flagged follow-up (DOC-11 §1.3):** skirnir has NO project/profile store (no serde/toml/eframe-storage). `(Y_c,Z_c,D)` live in app/wizard state for the run only; cross-session persistence is deferred — do not invent a persistence subsystem for it.

**Probe-failure semantics (deep-research-corrected):** a failed ALARMING probe (`G38.2`/`G38.4`) raises **ALARM:5** (no contact), NOT ALARM:4 (initial-state alarm); an active alarm locks g-code with `error:9`. The SILENT probes (`G38.3`/`G38.5`) do NOT alarm — they only set `:0`, so the success-flag check is the real guard. Firmware rejects an `A` word in any `G38.x` probe (linear-only) — wizards must index A outside every probe.

**Tests:** `protocol/probe.rs` (grammar + nan/inf reject), `protocol/response.rs` (parse_line + fall-through), `app/view_state.rs` (latch reducer), `app/probe_flow.rs` (decide gating, contact-Z zero, absolute backstop, shared `await_action`), `app/rotary_probe.rs` (5-line relative-probe sequence, no-A), `app/rotary_center.rs` (Yc/Zc math, MovedToYc order-enforced, failure aborts, G10 Y/Z-only L2, both Z datums + default), `app/shell.rs` (loopback: Z touch-off contact-zero + completion-gated `$#`; full 3-touch rotary run + failed abort + top-surface datum; cross-kind no-contamination; Door-suspend not-finished; wizard lost-push `$#`). 327 tests pass with `RUSTFLAGS="-D warnings"` (287 headless). `views.rs::probe_result` (ZeroZ-only) + `views.rs::rotary_center` render the flows.
